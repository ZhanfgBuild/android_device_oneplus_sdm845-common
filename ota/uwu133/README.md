# OnePlus6 uwu133 Retrofit Dynamic source profile — unvalidated

This directory contains a **byte-for-byte extracted fstab reference** from the
64-MiB OnePlus 6 17.0.101 `boot.img` confirmed on the user's device (SHA-256:
`6b305cace01270c797c7ad44a1457154ec91667227ce1e4b35be49156d940a0e`).
It is not the source or proof of a bootable 17.0.133 ROM.

What is verified from boot fstab and live probes:

- `/system`, `/vendor`, `/odm` are EROFS logical device-mapper partitions using
  `slotselect`, `first_stage_mount`, and AVB flags.
- `/metadata` is ext4 on physical `logdump`, *not* an assumed `metadata` GPT partition.
- `/data` remains ext4 FBE v2 with `fileencryption=aes-256-xts:aes-256-cts:v2`.
- Current device is `enchilada`, running 17.0.101 on slot A with a user-booted
  `4.19.325` BakaSU kernel.

What is **not** yet verified: physical partition byte capacities, dynamic
partition group capacity and lp metadata overhead; inactive-slot lp metadata,
recovery fstab injection into both first-stage boot and recovery ramdisks,
boot/AVB signing chain, vendor blobs ABI, target-files OTA integrity, 133-to-101
shared `/data` compatibility and real B-slot boot. No OTA should be delivered
before these are checked.

`BoardConfigRetrofit.mk` intentionally errors unless
`OP6_UWU133_LAYOUT_VERIFIED=true` **and** five independently verified byte
capacity variables are supplied. These are populated only after a separate
review of the phone's `lpdump` and `blockdev` report, never guessed from a
legacy partition table or a different SDM845 device.

The existing `init/fstab.qcom` Soong module is a **separate open integration
item**: the original common product installs a legacy fstab into vendor and
ramdisk. A complete OTA build must replace that first-stage installed fstab with
the EROFS profile, avoid duplicate install targets, and validate that the actual
`boot.img` regenerated by the ROM contains both copies. Changing only
`TARGET_RECOVERY_FSTAB` is not sufficient. This is a source migration checkpoint.

The A/B rollback promise covers only the old OS slot, not `/data`. Never auto
mark the updated slot successful before health gates and user approval. Android
`update_engine`/`bootctl` control slot switching; this repository's scripts are
read-only and do not invoke these controls.
